# Plumb 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Plumb 1.0.0: a Claude Code + Copilot CLI plugin that creates, extracts, prototypes,
audits and maintains a project's design system, exactly as the approved spec describes.

**Architecture:** Deterministic work lives in standard-library Python scripts (a token generator,
an audit, a prototype builder, a shared module) that are copied into each project's skill and
tested here; judgment work (interviews, directions, components, prototypes, walkthrough scripts)
lives in lean skills that call those scripts. Three hooks (session start, pre-edit, stop) run
through Slate's launchers in both tools.

**Tech Stack:** Python 3.9+ standard library only (shipped code); pytest (+ optional Playwright)
for tests; bash/cmd/PowerShell launchers; Markdown skills; self-contained HTML templates.

**Spec:** `docs/specs/2026-10-11-plumb-design.md` (approved 2026-10-11). Read it before any task.
Reference implementations (read only, never write there):
`~/Desktop/Zidane/keel/.claude/skills/keel-design-system/` (generator, audit, skill shape) and
`~/Desktop/Projects/gdtc-ai-products/slate/` (plugin packaging, hooks, launchers, tests, upgrade).

## Global Constraints

- Python **3.9+**, **standard library only** in everything under `plugins/plumb/` (no pip deps).
- Every Python entry point reconfigures stdout/stderr to UTF-8; every text read/write and
  subprocess call passes `encoding="utf-8"`; files written UTF-8 with `\n`; pathlib; no
  `shell=True` (`tests/test_portability.py` scans every `.py` under `plugins/plumb/` and `scripts/`).
- Works on Windows, macOS, Linux, over SSH and in tmux. Hooks go through `hooks/run.sh` and
  `hooks/run.cmd`; every hook in `hooks.json` has a `powershell` command.
- Every error/refusal: `error: …` then `fix: <exact command>` or `ask the user: …`; a test per
  refusal path. Scripts never print tracebacks to users; bad input exits 2.
- Generated files start with a `GENERATED … do not edit` header naming source and command.
- Generated pages load **nothing from the network** (no CDN, no hosted fonts); system font stacks
  or fonts embedded from the project's own files.
- Plumb never installs or downloads anything; skills say "ask the user and wait".
- Product text never mentions internal projects (no "Keel", "CareDesk" etc. in `plugins/`),
  except the committed golden example under `examples/`.
- Version **1.0.0** everywhere it lives (plugin.json, script `PLUMB_VERSION`, `templates/PLUMB.md`
  first line); tokens schema `1`.
- Commits: `<area>: <what changed>` + a short body listing verification. **No AI attribution**
  (no `Co-Authored-By`, no "Generated with"). Never commit `__pycache__`, `.pytest_cache`,
  `.DS_Store`.
- Tests first for every task: happy path + every refusal. Run
  `uv run --with pytest pytest -q` and `uv run --python 3.9 --with pytest pytest -q` before each
  commit.
- Browser checks are headless (`uv run --with playwright python …`, `launch(headless=True)`);
  browser tests skip with a reason when Playwright is not importable.

## Review Focus

1. **Windows paths and line endings** in every script and hook (backslashes, `C:\`, CRLF input
   files): tests in Tasks 3, 6, 12 feed CRLF files and Windows-style paths and expect identical
   results.
2. **Huge or minified files** (a 2 MB bundled CSS, a minified one-line JS): the audit must stay
   under its time budget and skip build output; Task 6 adds a minified-file test and a
   `node_modules`/`.next`/`dist` exclusion test.
3. **Unicode in content** (emoji in copy, non-Latin product names, `ü` in a path): Task 2 and
   Task 9 test a project named `Café Ünïcode` end to end.
4. **Malformed project files** (broken tokens JSON, a screen file with no `data-state`, a tour
   pointing at a removed element, a PLUMB.md with unknown keys): every script exits 2 with the
   offending file and line, hooks fail open; Tasks 5, 9, 10, 12 own these tests.
5. **Running twice** (re-running create/extract/build on an already-built project): outputs are
   byte-identical (idempotence tests in Tasks 3, 4, 9) and `[Y]` files are never overwritten.
