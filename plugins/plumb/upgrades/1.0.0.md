# Upgrade to 1.0.0

## What's new

The first release of Plumb. In plain words, you can now:

- set Plumb up in any project, in the right folder, with your OK at every step: `/plumb:init`;
- make a design system for a new project, from a few questions and 2–3 directions: `/plumb:create`;
- pull the design system out of an app you already have: `/plumb:extract`;
- prototype a screen before it is built, choosing between 2–3 variants with every state in light and dark:
  `/plumb:prototype billing`;
- write a walkthrough of the prototype for a client demo or training, and send it as one offline page:
  `/plumb:tour client-demo`;
- check the UI against the system and fix or improve it with your OK: `/plumb:audit`, `/plumb:audit fix`,
  `/plumb:audit improve`;
- review one screen's UX in depth: `/plumb:ux booking`;
- change the design, or add iOS and Android later: `/plumb:update add iOS`;
- see how healthy the design system is: `/plumb:status`.

While an agent builds, three hooks keep every edit on the system and check the changed screens before it hands back.
The complete guide is `docs/USAGE.md` in the Plumb repository.

## Steps

These steps run for a project set up before 1.0.0 (a preview build). A project set up with `/plumb:init` on 1.0.0 is
already current. A project set up on an early 1.0.0 build whose `PLUMB.md` has no `Routes:` line keeps working, but
the prototype-first check and `route-not-prototyped` stay off (session start and `scaffold.py --verify` say "Routes
not recorded"): run `/plumb:init`, which offers to record it.

### 1. Record the app's page roots
**Check:** `PLUMB.md` has no `Routes:` line → needed.
**Do:** investigate where the app keeps its pages (interview.md "What gets recorded"), count what each root holds, and
ask, with that evidence inside the question: "Record `Routes: <path> (<kind>)`?" (a) Yes (Recommended) (b) Change it
(c) `none` (no web pages: mobile only, design only). Write the line under `## Checks` only on yes, then run
`scaffold.py --verify` and show its `Routes:` line.

### 2. Tailwind's default scales
**Check:** the tokens file has no `$extensions.plumb.web.reset_palette` and the styling is Tailwind → needed.
**Do:** `build-tokens.py --migrate` records `true` (what the block already did). When the app's UI files use Tailwind
palette classes, say how many inside a question and offer: keep them working, `false` (Recommended: the audit then
suggests moving them onto tokens) · keep the reset, `true`. Change the value only on the user's answer, then rebuild.
